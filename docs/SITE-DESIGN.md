# Granite Reserving: Site Design

Last updated October 2, 2026. Companion to [SCOPE.md](SCOPE.md).

## The short version

- **Python and Excel do the work** in this repo. The website only **shows finished results**.
- The site has **one page per step** of the project. On each page you can click a formula, a term or a step, and a **popup** explains the reasoning, the derivation and which exam or course it comes from.
- Two kinds of content, kept in separate places so one never overwrites the other:
  - **Numbers** (triangles, reserve bridge, ranges) are generated by Python.
  - **Explanations** (the popups) are written by you in plain markdown files.
- They are joined by an **ID**, for example `mack-1994-se`.

## How it flows

```
Python (simulate, reserve, price)  ->  export script  ->  site-bundle/ (JSON)  ->  Leo's Log page
Your notes (notes/*.md)            ->  export script  ->  site-bundle/notes/    ->  popups
```

Leo's Log (React, Supabase, Cloudflare Worker) never runs actuarial code. It reads the JSON and draws it.

## Folders to add to this repo

```
notes/         your writing, one markdown file per concept (the popup content)
export/        the script that builds the bundle
site-bundle/   generated output, never edited by hand
  manifest.json
  steps/01-simulator.json ... 08-capital.json
  data/        triangles, bridge, ranges, scores (JSON)
  notes/       notes compiled to JSON
```

## A note file (what a popup shows)

File: `notes/mack-1994-se.md`

```markdown
---
id: mack-1994-se
title: Mack standard error of the chain ladder
source: { kind: paper, ref: "Mack (1994)", exam: "7" }
also_uses: [{ kind: course, ref: "STAC67", why: "regression through the origin" }]
steps: [05-stochastic]
code: reserving/stochastic/mack.py
test: tests/test_mack_friedland.py
unlock: null
---
## Why
One or two sentences on why this is used.

## Derivation
$$\hat\sigma_k^2 = \frac{1}{n-k-1}\sum_i C_{i,k}\left(\frac{C_{i,k+1}}{C_{i,k}}-\hat f_k\right)^2$$

## When it fails
What assumption breaks and how to tell.
```

Every popup has the same sections: **Why, Derivation, Where it comes from, When it fails, Code and test.** That makes the notes double as study notes.

- `unlock: null` means visible now. Use `unlock: phase6` for anything that would spoil the sealed truth.

## Making things clickable

Pre-mark what is clickable. Do not rely on visitors highlighting free text, because mapping a selection to a note is fragile and works badly on phones.

- **In prose:** `[chain ladder]{mack-1994-se}` shows a dotted underline that opens the popup.
- **Inside a formula:** KaTeX can wrap parts of an equation, so each symbol can be its own click target.
- **Direct link:** `?note=mack-1994-se` opens that popup, so a post can link to one note.
- **Phone:** the popup becomes a bottom sheet.

## Popups can show live numbers

A note can point at an export so the popup shows the real figure next to the theory. For example: "selected 12-24 factor = 1.874; all-year 1.861; latest-3 1.902; why I picked it."

## Getting the bundle onto the site

Start simple: copy `site-bundle/` into the Leo's Log repo as static files (for example `public/big-one/`) and deploy with `publish-to-github.cmd`. Results change a few times a year, so this is enough. A Supabase row only makes sense later if you want updates without a deploy.

## Rules for the bundle

1. **Never export the sealed truth, the planted-changes log or the scores before Phase 6.** A build check should fail if any file marked `unlock: phase6` or any score file appears earlier. This matters most if the repo is public.
2. **Everything is fictional.** No real company data in any export.
3. **Raw Parquet data stays out** of the bundle and out of git.

## Open decisions

- Does Leo's Log already render LaTeX? If not, add `remark-math` and `rehype-katex`.
